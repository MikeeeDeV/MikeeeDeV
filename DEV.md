## 2. Hard Invariants & Engineering Guarantees

1. **Zero Runtime Dependency**: No third-party servers (`shields.io`, `github-readme-stats`, `vercel.app`, `herokuapp.com`, `komarev.com`). Everything visual is an SVG generated by our scripts and served directly from GitHub.
2. **Zero-Crash Network Resilience**: Every API fetch catches exceptions and gracefully falls back to `data/cache/*.json`. If the GitHub API is down, rate-limited, or unreachable, generation still completes with pristine, last-known-good assets.
3. **Dual Theme Adaptation**: Every SVG embeds `:root` variables and `@media (prefers-color-scheme: light)` to adapt seamlessly to GitHub's light and dark themes.
4. **Size Budget**: Every SVG must remain strictly under **100KB**.
5. **Accessibility**: Every SVG contains explicit `<title>` and `<desc>` elements for screen readers.

## 3. Local Development Workflows

### With Make:
```bash
# Build all SVGs and update README sections
make build

# Run unit tests and SVG snapshot validation
make test

# Full check (build + test)
make check

# Preview locally on http://localhost:8080
make preview
```

### With Nix Flake (Hermetic):
```bash
# Enter isolated developer shell with pinned Python, git, and gh toolchains
nix develop

# Build deterministic output package into result/
nix build
```

## 4. Editing Status (`now.yml`)

To update what you are currently building, simply edit `now.yml`:
```yaml

shipping:
  project: "NixManagerPro"
  repo: "MikeeeDeV/NixManagerPro"
  status: "Shipping v1.7.0"
  tagline: "Asynchronous multi-channel Nix package manager"
  milestone: "v1.7.0 Released"
```

Running `make build` (or pushing to GitHub) will update both `assets/now-building.svg` and the corresponding section in `README.md`.

## 5. The Visitor Terminal (GitHub Actions)

Visitors trigger the terminal by opening an issue with a title starting with `terminal:`:
- `terminal: ping` — Returns workstation latency and status.
- `terminal: vouch "<message>"` — Records a greeting or endorsement into `data/visitors.json`.
- `terminal: inspect <repo>` — Audits repository derivations.
- `terminal: quote` — Returns a systems philosophy quote.

The workflow `.github/workflows/visitor-terminal.yml`:
1. Validates the command against a strict whitelist.
2. Sanitizes input strings (max 50 chars, no HTML/markdown injection).
3. Appends the entry to `data/visitors.json`.
4. Re-renders `assets/visitor-ledger.svg`.
5. Commits the changes with `[skip ci]`.
6. Auto-closes the issue with a styled receipt comment.

## 6. Adding a New Generator

1. Create `scripts/generate_<feature>.py`.
2. Import `tokens` and `get_root_css` from `common.py`.
3. Wrap your SVG markup with accessibility tags (`<title>` and `<desc>`).
4. Register your generator in `scripts/run_all.py` and `tests/test_svg_snapshots.py`.
5. Run `make check` to verify validation passes.
